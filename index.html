Batch size for whole agent traces

This Agent Probe experiment ran Llama-3.1-8B AWQ on one NVIDIA H100.

As the batch grew from 1 to 32 concurrent agents, mean time for the complete batch to finish rose from 1.11 s to 4.52 s.

What changes when Agent Probe is enabled?

I ran a fixed-decode baseline without tool execution, conversation state, or an agent loop. It measures inter-token latency for fixed-length generation requests at each batch size.

For the Agent Probe experiment, a probe-driver script creates one independent retrieval agent for every slot in the batch. Each agent receives the same local question, uses search and document-retrieval tools, incorporates the returned observations into its own conversation, and produces a final answer. A trace therefore spans multiple model turns, tool calls, growing context, and a final answer.

What "batch size N" means here: it is a batch of N independent agent requests, not one request with an internal batch size of N. On each active turn, the driver submits the next model input from every unfinished agent together. When an agent finishes, it is removed from later turn batches.

How the probe driver runs a trace

The script replaces the one-shot benchmark loop with a turn-by-turn scheduler. For every active agent it gathers the next model input, sends all of those inputs as one model batch, executes any requested tool locally, appends that tool result to that agent's own history, then advances to the next round. Whole-trace elapsed time runs from the first model submission until all agents in the batch have finished.

The driver batches only active model turns. Local tool execution and variable trace length are part of the reported wall-clock time.

The amount of work per trace remained broadly comparable: agents used about 3.6-4.5 model turns and around 200 generated tokens. The rise in completion time therefore tracks concurrency more than a systematic change in task length. Tool time and model time are both included in wall-clock duration.

How to interpret the trace result

This is an early characterization, not a general latency law. There are only four batches per size, and an agent can legitimately take a different path or finish after a different number of turns. The batch CV ranges from 1.8% to 30.6%. The recorded trace data also includes final context length, tool time, and a 10 ms GPU-power trace, but the summary above does not attribute elapsed time to individual kernels or tools.

Fixed-length decode baseline (without Agent Probe)

The supporting microbenchmark used the same H100 and Llama-3.1-8B AWQ model, with 256 input and 512 output tokens. It submitted N fixed requests concurrently and measured a target request's stable inter-token latency. Across two launches and 12 paired repeats per size, the increase versus N=1 was 0.95%, 2.82%, 5.73%, 11.12%, and 29.67% at N=2, 4, 8, 16, and 32. It explains decode contention, but it is separate from an agent's variable-length, tool-using trace.

Scope and data

The Agent Probe results apply to this local retrieval-agent task, one H100 allocation, Llama-3.1-8B AWQ, and the six tested sizes. They do not establish performance for different models, tool backends, contexts, hardware, or N greater than 32.
